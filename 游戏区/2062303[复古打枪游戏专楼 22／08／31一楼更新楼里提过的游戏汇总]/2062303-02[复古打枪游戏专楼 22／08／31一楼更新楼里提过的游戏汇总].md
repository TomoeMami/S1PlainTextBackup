SyncError 分享《Quake Champions》的开发细节

前《Quake Champions》开发人员 SyncError 在近期的一场 LeadHead Twitch 直播中，透露了这款游戏开发过程中的诸多细节（[[https://www.twitch.tv/videos/2925974396](https://www.twitch.tv/videos/2925974396)）。]([https://www.twitch.tv/videos/292 ... _source=chatgpt.com](https://www.twitch.tv/videos/2925974396%EF%BC%89%E3%80%82?utm_source=chatgpt.com))

B%E3%80%82SyncError](https://www.youtube.com/watch?v=1URVnTHBzgg%EF%BC%89%E3%80%82%E8%AF%A5%E8%A7%86%E9%A2%91%E5%9B%9E%E9%A1%BE%E4%BA%86%E6%B8%B8%E6%88%8F%E7%9A%84%E5%BC%80%E5%8F%91%E5%8E%86%E7%A8%8B%E3%80%81%E9%A2%87%E5%85%B7%E4%BA%89%E8%AE%AE%E7%9A%84%E8%AE%BE%E8%AE%A1%E5%86%B3%E7%AD%96%EF%BC%8C%E4%BB%A5%E5%8F%8A%E6%9C%80%E7%BB%88%E6%9C%AA%E8%83%BD%E5%AE%9E%E7%8E%B0%E7%9A%84%E6%BD%9C%E5%8A%9B%E3%80%82SyncError)\&amp;utm_source=chatgpt.com) 在直播期间加入聊天室，纠正了视频中的一些说法，并补充了自己参与游戏开发期间的相关背景。

今年早些时候，SyncError 已经停止参与《Quake Champions》的后续更新工作（[[https://www.plusforward.net/post ... -Champions-updates/](https://www.plusforward.net/post/95980/SyncError-says-he-is-no-longer-working-on-Quake-Champions-updates/)）。他同时指出，自己能够透露的信息仍然有限。直播期间，他表示自己仍在领取公司的薪酬，并称自己的保密协议（NDA）“永不过期”。]([https://www.plusforward.net/post ... _source=chatgpt.com](https://www.plusforward.net/post/95980/SyncError-says-he-is-no-longer-working-on-Quake-Champions-updates/%EF%BC%89%E3%80%82%E4%BB%96%E5%90%8C%E6%97%B6%E6%8C%87%E5%87%BA%EF%BC%8C%E8%87%AA%E5%B7%B1%E8%83%BD%E5%A4%9F%E9%80%8F%E9%9C%B2%E7%9A%84%E4%BF%A1%E6%81%AF%E4%BB%8D%E7%84%B6%E6%9C%89%E9%99%90%E3%80%82%E7%9B%B4%E6%92%AD%E6%9C%9F%E9%97%B4%EF%BC%8C%E4%BB%96%E8%A1%A8%E7%A4%BA%E8%87%AA%E5%B7%B1%E4%BB%8D%E5%9C%A8%E9%A2%86%E5%8F%96%E5%85%AC%E5%8F%B8%E7%9A%84%E8%96%AA%E9%85%AC%EF%BC%8C%E5%B9%B6%E7%A7%B0%E8%87%AA%E5%B7%B1%E7%9A%84%E4%BF%9D%E5%AF%86%E5%8D%8F%E8%AE%AE%EF%BC%88NDA%EF%BC%89%E2%80%9C%E6%B0%B8%E4%B8%8D%E8%BF%87%E6%9C%9F%E2%80%9D%E3%80%82?utm_source=chatgpt.com))

他分享的细节包括：

• Saber 专门开发了一套工具，用于直接对比《Quake Champions》和《Quake Live》的移动机制。根据 SyncError 的介绍，这套工具会读取玩家的输入，并将其同时发送给两个独立客户端：一个运行《Quake Live》，另一个运行基于 Saber 引擎的《Quake Champions》原型。其目的是复现《Quake Live》的移动机制与操作手感，并验证两款游戏在接受相同输入时能否产生可比较的结果。

• id Software 在早期技术讨论中曾考虑使用 id Tech 3、4 和 5。当时 id Tech 6 尚未完成。团队考虑的方案并不局限于直接使用旧引擎，例如，可以保留 id Tech 3 并替换其渲染器，也可以采用 id Tech 5 并使用不同的网络系统。SyncError 补充说，这些方案最终遭到否决的原因，此前并未得到广泛讨论。

• 从 DOOM 项目调走开发人员从来不在考虑范围之内。根据 SyncError 的说法，当时 id Software 连从《DOOM》（2016）项目中抽调“哪怕一个人”都不愿意，因为那是工作室当时的主要内部项目。转移这些开发资源根本不在讨论范围之内。

• Saber 当时已经使用自家引擎开发了约20至25年。SyncError 表示，该工作室此前从未基于其他代码库进行开发。他也反驳了该引擎本质上属于主机引擎的说法，指出 Saber 曾经使用它开发原生游戏，而引擎本身只是支持多平台开发。

• SyncError 将《Quake Champions》描述为 id Software 将精力集中于其他项目期间，维持 Quake 系列生命力的一种方式。他认为，团队当时面临的选择是：要么可能连续多年都没有新的 Quake 作品，要么开发一些规模较小的支线项目，以维持系列的活跃度。在他看来，《Quake Live》和《Quake Champions》都属于后一种做法。

• Quake 开发外包并非《Quake Champions》才有的先例。SyncError 指出，《Quake 4》由 Raven Software 与 id Software 合作开发，而《Enemy Territory: Quake Wars》则由 Splash Damage 开发。不过，他也认同，只要条件允许，id Software 大概还是应该尽可能在内部开发 Quake。

• SyncError 为外部 Quake 开发团队所完成的工作进行了辩护。他称《Enemy Territory: Quake Wars》是一款出色的竞技游戏，尽管它“在引擎层面有很多毛病”，但 Splash Damage 仍然成功地将源自《Quake 4》引擎的技术应用于规模大得多的游戏环境中。他同时提醒，不应该将《Quake Champions》的问题简单归咎于 Saber，因为这家工作室里有“很多优秀的人”。

• 《Quake Champions》没有一位唯一的主设计师。根据 SyncError 的说法，Tim Willits 担任执行层面的角色，Saber 有自己的负责人，而 SyncError 本人也担任项目负责人之一。他将这个项目描述为需要所有人持续共同引导的工作，而非由某一位主设计师按照个人愿景独自打造的游戏。

• 《Quake Champions》的早期版本拥有完整的录像回放功能。服务器会将服务器端 demo 写入后端存储系统，玩家则可以通过浏览器界面查找并观看已经录制的比赛。SyncError 表示，这套系统允许客户端查找和观看任何已经录制的比赛。

• 移动处理从客户端迁移到服务器端后，录像系统也受到了影响。根据 SyncError 的说法，原本的回放功能在这次调整之前就已经存在。但当移动逻辑转移到服务器端处理之后，回放系统便需要进行大幅改造。

• 如果《Quake Champions》取得成功，游戏原本计划加入 Mod 支持。SyncError 表示，只要游戏取得成功，并且持续获得早期开发阶段那样的支持，Mod“始终都会到来”。

• Scrag Battle 确实是一种实际开发过的实验模式，只是开发者最终觉得它不够有趣。早在2018年，《Quake Champions》的游戏数据中就已经出现了 Scrag Battle 的相关痕迹，其中的描述称玩家需要收集代币，并击败生成出来的 Scrag。SyncError 在直播中对此给出了更加直接的解释：“Scrag Battle 不好玩”，因此这项模式最终没有继续推进。

• 早期版本还包含其他开发程度相当高的功能。SyncError 表示，游戏曾经拥有一套完全可用的“钥匙”（keys）功能，但他没有解释其预期用途，也没有说明它最终被移除的原因。他还提到一套完成度约为80%的“player killer card system”，但没有提供足够的背景信息来确定其具体设计。

• 《Quake Champions》的引擎在早期开发结束后仍然持续演进。针对有人认为引擎实际上已经停止更新的说法，SyncError 回应称，过去七年里发生了“大量引擎改动”。他以自己加入 picmip 功能为例，说明这项功能本身就需要进行引擎层面的开发。

• SyncError 不认为 Havok 之类的中间件本身存在问题。他确认《Quake Champions》使用了 Havok，并表示这类中间件“没问题”。

• SyncError 强烈反对将《Quake Champions》视为英雄射击游戏。他的表述十分明确：“这不是英雄射击游戏，从来就不是。”在他看来，主动技能更像是叠加在 Quake 原有玩法之上的额外武器或工具，而不是将各位 Champion 变成传统意义上的角色职业。

• 他将主动技能与《Quake Live》中已有的道具进行了比较。SyncError 认为，如果有人抱怨某项技能没有让角色变成传统职业，那么这就像抱怨《Quake Live》的医疗包没有让使用者真正拥有医疗兵的感觉。这些技能只是辅助核心玩法的工具，并不会取代游戏原有的核心玩法。

• 被动技能和移动方式才是开发团队原本希望用来定义玩家玩法的部分。SyncError 表示：“被动技能决定你的玩法。”不同的移动风格旨在让玩家选择自己偏好的 Quake 移动方式，而主动技能并不会从根本上改变游戏。

• Champion 系统的设计也部分借鉴了 Quake Mod 中存在数十年的思路。SyncError 回忆，自己曾经是一名 CTF 玩家，在这种模式中，队友本来就会承担不同的位置，并拾取能够赋予他们相应能力的符文或强化道具。他强调，《Quake Champions》并未直接复现旧有的职业系统，只是在构建相似的设计理念。

• SyncError 还回忆起 Overwatch、Unreal Tournament 4 和 Epic 的 Paragon 在大致同一时期公布的情形。他表示，自己记得当时坐在会议室里，听到了《Overwatch》的公布消息；《Unreal Tournament 4》和 Epic 的《Paragon》也发生在那个时期。直播中，当讨论转向更传统的职业式 Champion 定位时，他回应道：“我们不会朝那个方向做。我们不想那样做。那不是 Quake。”

• Quake 丰富的游戏模式既是其巨大优势，也是一个重大难题。SyncError 认为，成功的多人游戏通常会有一种让人立即联想到该游戏的核心玩法，但 Quake 已经围绕 Duel、TDM、CTF、Sacrifice 等多种模式形成了各自的玩家社群。在他看来，这种多样性既是“巨大的加分项”，也是“一个大问题”。

• SyncError 欣赏《Team Fortress 2》和《Counter-Strike》处理玩法差异的方式。他指出，这两款游戏可以通过地图本身带来玩法上的变化，同时又保持鲜明、易于辨认的核心身份。就个人而言，他觉得 Deathmatch 的随机性太强，因此更喜欢 TDM 和 Sacrifice。

• Duel 始终是《Quake Champions》最强的观赛模式。当 Twitch 聊天室讨论 Duel 的受欢迎程度时，SyncError 表示它“始终占据主导地位”，而且是一种非常适合观看的模式。

• CTF 加入《Quake Champions》时，团队已经失去了能够妥善支持这一模式的人手。SyncError 表示，等到 CTF 真正出现时，“我们已经没有团队了”。在他看来，这一模式需要大约十几张质量出色、布局对称的地图，因此要做好 CTF，远远不只是实现夺旗机制那么简单。

• SyncError 不认为仅靠教程就能解决 Quake 的易上手性问题。他承认教程能够帮助玩家，但像 strafe jumping（侧向跳跃）这样的机制，很难通过短时间教学让足够广泛的玩家群体掌握。他同时指出，许多玩家也不愿意在开始游戏之前，先花费大量时间完成强制训练。

• 一次 E3 展示充分说明，即使是热衷其他游戏的玩家，也可能很难上手 Quake。根据 SyncError 的说法，团队最后只能展示 Instagib，因为现场观众连 TDM 都应付不了。即使改成 Instagib，他们仍然很难命中对手。他将这些观众形容为“热衷于其他游戏的玩家”。

• SyncError 认为，竞技场式 FPS 中的“竞技场”部分尤其容易成为新玩家的障碍。他指出，Quake 的速度以及持续进行空间态势判断的要求，与许多其他射击游戏存在显著差异。敌人未必就在玩家正前方、处于同一高度，玩家还必须应对来自多个方向和不同高度的攻击。

• 为每位 Champion 制作详尽教程，会消耗大量开发资源。SyncError 估计，单独为一名 Champion 制作一套完善的教程，大约需要三个月。如果当时有十几名 Champion，那么制作这些教程就意味着游戏中其他已经存在的内容将不得不缺席。

• 玩家确实有办法在不永久购买 Champion 的情况下体验角色。SyncError 指出，游戏提供过 Champion 租用机制。尤其是在开发早期，玩家可以使用免费获得的 Favor 暂时租用这些角色。

• SyncError 认为，《Quake Champions》的核心仍然是竞争。他指出，即使是休闲多人游戏，玩家之间也始终存在竞争，无论对手是职业选手还是自己的朋友。在他看来，只包含多人模式的 Quake 自然会围绕竞争展开；如果希望系列从根本上围绕其他主题展开，就需要一款单人游戏。

• SyncError 将主要为了奖励而游玩称作一种“诅咒”。他认为，奖励系统可能让玩家沉迷于完成奖励任务，而不是享受游戏本身。如果游戏系统的调整主要是为了提高用户参与度，游戏玩法也可能因此失去平衡。

• 他将现代奖励系统与过去玩家单纯因为喜欢 Quake 而投入大量精力的情形进行了对比。SyncError 回忆，最初的《Quake》并没有集成多人服务器浏览器，玩家需要通过控制台输入 IP 地址连接服务器。根据他的说法，服务器浏览器后来随《QuakeWorld》出现，《Quake II》也有自己的服务器浏览器，而《Quake III》至少提供了主服务器列表。他想表达的重点是，玩家愿意付出相当多的努力来玩一款游戏，因为他们真正投入其中。

• SyncError 起初反对节日主题的外观内容，但后来改变了对其中一部分内容的看法。他表示，自己最初并不希望加入节日主题内容，不过后来喜欢上了高顶礼帽和厨师帽之类的物品。他既喜欢严肃的世界观设定，也喜欢刻意荒诞、彻底恶搞的内容。

• SyncError 认为，《Quake Champions》首支 CGI 预告片作为先导宣传片效果很好，但游戏之后缺少有力的后续视频。他称最初的预告片“很棒”，但认为之后还需要推出其他优秀视频。他对此颇为遗憾，并表示：“而我们从来没有做到这一点。”

• SyncError 表示，Quake 社群在每一代续作推出时都会发生分裂。在围绕整个系列的讨论中，他写道，社群“每一代续作都会迅速壮大——然后分裂”。

他分享的细节包括：

• Saber 专门开发了一套工具，用于直接对比《Quake Champions》和《Quake Live》的移动机制。根据 SyncError 的介绍，这套工具会读取玩家的输入，并将其同时发送给两个独立客户端：一个运行《Quake Live》，另一个运行基于 Saber 引擎的《Quake Champions》原型。其目的是复现《Quake Live》的移动机制与操作手感，并验证两款游戏在接受相同输入时能否产生可比较的结果。

• id Software 在早期技术讨论中曾考虑使用 id Tech 3、4 和 5。当时 id Tech 6 尚未完成。团队考虑的方案并不局限于直接使用旧引擎，例如，可以保留 id Tech 3 并替换其渲染器，也可以采用 id Tech 5 并使用不同的网络系统。SyncError 补充说，这些方案最终遭到否决的原因，此前并未得到广泛讨论。

• 从 DOOM 项目调走开发人员从来不在考虑范围之内。根据 SyncError 的说法，当时 id Software 连从《DOOM》（2016）项目中抽调“哪怕一个人”都不愿意，因为那是工作室当时的主要内部项目。转移这些开发资源根本不在讨论范围之内。

• Saber 当时已经使用自家引擎开发了约20至25年。SyncError 表示，该工作室此前从未基于其他代码库进行开发。他也反驳了该引擎本质上属于主机引擎的说法，指出 Saber 曾经使用它开发原生游戏，而引擎本身只是支持多平台开发。

• SyncError 将《Quake Champions》描述为 id Software 将精力集中于其他项目期间，维持 Quake 系列生命力的一种方式。他认为，团队当时面临的选择是：要么可能连续多年都没有新的 Quake 作品，要么开发一些规模较小的支线项目，以维持系列的活跃度。在他看来，《Quake Live》和《Quake Champions》都属于后一种做法。

• Quake 开发外包并非《Quake Champions》才有的先例。SyncError 指出，《Quake 4》由 Raven Software 与 id Software 合作开发，而《Enemy Territory: Quake Wars》则由 Splash Damage 开发。不过，他也认同，只要条件允许，id Software 大概还是应该尽可能在内部开发 Quake。

• SyncError 为外部 Quake 开发团队所完成的工作进行了辩护。他称《Enemy Territory: Quake Wars》是一款出色的竞技游戏，尽管它“在引擎层面有很多毛病”，但 Splash Damage 仍然成功地将源自《Quake 4》引擎的技术应用于规模大得多的游戏环境中。他同时提醒，不应该将《Quake Champions》的问题简单归咎于 Saber，因为这家工作室里有“很多优秀的人”。

• 《Quake Champions》没有一位唯一的主设计师。根据 SyncError 的说法，Tim Willits 担任执行层面的角色，Saber 有自己的负责人，而 SyncError 本人也担任项目负责人之一。他将这个项目描述为需要所有人持续共同引导的工作，而非由某一位主设计师按照个人愿景独自打造的游戏。

• 《Quake Champions》的早期版本拥有完整的录像回放功能。服务器会将服务器端 demo 写入后端存储系统，玩家则可以通过浏览器界面查找并观看已经录制的比赛。SyncError 表示，这套系统允许客户端查找和观看任何已经录制的比赛。

• 移动处理从客户端迁移到服务器端后，录像系统也受到了影响。根据 SyncError 的说法，原本的回放功能在这次调整之前就已经存在。但当移动逻辑转移到服务器端处理之后，回放系统便需要进行大幅改造。

• 如果《Quake Champions》取得成功，游戏原本计划加入 Mod 支持。SyncError 表示，只要游戏取得成功，并且持续获得早期开发阶段那样的支持，Mod“始终都会到来”。

• Scrag Battle 确实是一种实际开发过的实验模式，只是开发者最终觉得它不够有趣。早在2018年，《Quake Champions》的游戏数据中就已经出现了 Scrag Battle 的相关痕迹，其中的描述称玩家需要收集代币，并击败生成出来的 Scrag。SyncError 在直播中对此给出了更加直接的解释：“Scrag Battle 不好玩”，因此这项模式最终没有继续推进。

• 早期版本还包含其他开发程度相当高的功能。SyncError 表示，游戏曾经拥有一套完全可用的“钥匙”（keys）功能，但他没有解释其预期用途，也没有说明它最终被移除的原因。他还提到一套完成度约为80%的“player killer card system”，但没有提供足够的背景信息来确定其具体设计。

• 《Quake Champions》的引擎在早期开发结束后仍然持续演进。针对有人认为引擎实际上已经停止更新的说法，SyncError 回应称，过去七年里发生了“大量引擎改动”。他以自己加入 picmip 功能为例，说明这项功能本身就需要进行引擎层面的开发。

• SyncError 不认为 Havok 之类的中间件本身存在问题。他确认《Quake Champions》使用了 Havok，并表示这类中间件“没问题”。

• SyncError 强烈反对将《Quake Champions》视为英雄射击游戏。他的表述十分明确：“这不是英雄射击游戏，从来就不是。”在他看来，主动技能更像是叠加在 Quake 原有玩法之上的额外武器或工具，而不是将各位 Champion 变成传统意义上的角色职业。

• 他将主动技能与《Quake Live》中已有的道具进行了比较。SyncError 认为，如果有人抱怨某项技能没有让角色变成传统职业，那么这就像抱怨《Quake Live》的医疗包没有让使用者真正拥有医疗兵的感觉。这些技能只是辅助核心玩法的工具，并不会取代游戏原有的核心玩法。

• 被动技能和移动方式才是开发团队原本希望用来定义玩家玩法的部分。SyncError 表示：“被动技能决定你的玩法。”不同的移动风格旨在让玩家选择自己偏好的 Quake 移动方式，而主动技能并不会从根本上改变游戏。

• Champion 系统的设计也部分借鉴了 Quake Mod 中存在数十年的思路。SyncError 回忆，自己曾经是一名 CTF 玩家，在这种模式中，队友本来就会承担不同的位置，并拾取能够赋予他们相应能力的符文或强化道具。他强调，《Quake Champions》并未直接复现旧有的职业系统，只是在构建相似的设计理念。

• SyncError 还回忆起 Overwatch、Unreal Tournament 4 和 Epic 的 Paragon 在大致同一时期公布的情形。他表示，自己记得当时坐在会议室里，听到了《Overwatch》的公布消息；《Unreal Tournament 4》和 Epic 的《Paragon》也发生在那个时期。直播中，当讨论转向更传统的职业式 Champion 定位时，他回应道：“我们不会朝那个方向做。我们不想那样做。那不是 Quake。”

• Quake 丰富的游戏模式既是其巨大优势，也是一个重大难题。SyncError 认为，成功的多人游戏通常会有一种让人立即联想到该游戏的核心玩法，但 Quake 已经围绕 Duel、TDM、CTF、Sacrifice 等多种模式形成了各自的玩家社群。在他看来，这种多样性既是“巨大的加分项”，也是“一个大问题”。

• SyncError 欣赏《Team Fortress 2》和《Counter-Strike》处理玩法差异的方式。他指出，这两款游戏可以通过地图本身带来玩法上的变化，同时又保持鲜明、易于辨认的核心身份。就个人而言，他觉得 Deathmatch 的随机性太强，因此更喜欢 TDM 和 Sacrifice。

• Duel 始终是《Quake Champions》最强的观赛模式。当 Twitch 聊天室讨论 Duel 的受欢迎程度时，SyncError 表示它“始终占据主导地位”，而且是一种非常适合观看的模式。

• CTF 加入《Quake Champions》时，团队已经失去了能够妥善支持这一模式的人手。SyncError 表示，等到 CTF 真正出现时，“我们已经没有团队了”。在他看来，这一模式需要大约十几张质量出色、布局对称的地图，因此要做好 CTF，远远不只是实现夺旗机制那么简单。

• SyncError 不认为仅靠教程就能解决 Quake 的易上手性问题。他承认教程能够帮助玩家，但像 strafe jumping（侧向跳跃）这样的机制，很难通过短时间教学让足够广泛的玩家群体掌握。他同时指出，许多玩家也不愿意在开始游戏之前，先花费大量时间完成强制训练。

• 一次 E3 展示充分说明，即使是热衷其他游戏的玩家，也可能很难上手 Quake。根据 SyncError 的说法，团队最后只能展示 Instagib，因为现场观众连 TDM 都应付不了。即使改成 Instagib，他们仍然很难命中对手。他将这些观众形容为“热衷于其他游戏的玩家”。

• SyncError 认为，竞技场式 FPS 中的“竞技场”部分尤其容易成为新玩家的障碍。他指出，Quake 的速度以及持续进行空间态势判断的要求，与许多其他射击游戏存在显著差异。敌人未必就在玩家正前方、处于同一高度，玩家还必须应对来自多个方向和不同高度的攻击。

• 为每位 Champion 制作详尽教程，会消耗大量开发资源。SyncError 估计，单独为一名 Champion 制作一套完善的教程，大约需要三个月。如果当时有十几名 Champion，那么制作这些教程就意味着游戏中其他已经存在的内容将不得不缺席。

• 玩家确实有办法在不永久购买 Champion 的情况下体验角色。SyncError 指出，游戏提供过 Champion 租用机制。尤其是在开发早期，玩家可以使用免费获得的 Favor 暂时租用这些角色。

• SyncError 认为，《Quake Champions》的核心仍然是竞争。他指出，即使是休闲多人游戏，玩家之间也始终存在竞争，无论对手是职业选手还是自己的朋友。在他看来，只包含多人模式的 Quake 自然会围绕竞争展开；如果希望系列从根本上围绕其他主题展开，就需要一款单人游戏。

• SyncError 将主要为了奖励而游玩称作一种“诅咒”。他认为，奖励系统可能让玩家沉迷于完成奖励任务，而不是享受游戏本身。如果游戏系统的调整主要是为了提高用户参与度，游戏玩法也可能因此失去平衡。

• 他将现代奖励系统与过去玩家单纯因为喜欢 Quake 而投入大量精力的情形进行了对比。SyncError 回忆，最初的《Quake》并没有集成多人服务器浏览器，玩家需要通过控制台输入 IP 地址连接服务器。根据他的说法，服务器浏览器后来随《QuakeWorld》出现，《Quake II》也有自己的服务器浏览器，而《Quake III》至少提供了主服务器列表。他想表达的重点是，玩家愿意付出相当多的努力来玩一款游戏，因为他们真正投入其中。

• SyncError 起初反对节日主题的外观内容，但后来改变了对其中一部分内容的看法。他表示，自己最初并不希望加入节日主题内容，不过后来喜欢上了高顶礼帽和厨师帽之类的物品。他既喜欢严肃的世界观设定，也喜欢刻意荒诞、彻底恶搞的内容。

• SyncError 认为，《Quake Champions》首支 CGI 预告片作为先导宣传片效果很好，但游戏之后缺少有力的后续视频。他称最初的预告片“很棒”，但认为之后还需要推出其他优秀视频。他对此颇为遗憾，并表示：“而我们从来没有做到这一点。”

• 围绕 Quake 实际游戏画面的营销存在一个两难局面。缺乏经验的玩家可能让 Quake 的表现难以得到有效展示，而高手的操作速度又极快，新观众很难看清其中的内容。SyncError 还指出，近几年高速游戏的预告片已经越来越常见；如果在2015年的宣传视频中展示类似现代《ULTRAKILL》的战斗场面，当时简直难以想象。

• SyncError 认为，一支旧版《Quake Live》预告片是展示 Quake 实际玩法的最佳范例之一。他表示，自己曾经负责委托制作这支《Quake Live》预告片（[[https://www.youtube.com/watch?v=4aNG7cd7rGM](https://www.youtube.com/watch?v=4aNG7cd7rGM)），并称这是团队迄今展示游戏玩法最成功的一次。他也承认视频存在问题，尤其是击杀提示信息本应该删掉，但仍然将它视为更好的示范。]([https://www.youtube.com/watch?v= ... • 《Quake Live》在制作实机视频方面还拥有一项重要优势。SyncError 指出，当时《Quake Live》已经积累了约十年的击杀集锦视频制作工具和经验，而《Quake Champions》的实机画面却是在游戏仍处于积极开发阶段时录制的。两者在制作条件方面存在很大差别。

• 《Quake Champions》早期实机预告片的录制条件也相当别扭。根据 SyncError 的说法，画面由一名使用手柄进行观战的人录制，而真正参与游戏的玩家则被要求关闭常规 UI 和 HUD，连准星也不能显示。这样安排的原因，是制作团队不希望这些界面元素出现在视频里。

• SyncError 表示，Quake 社群在每一代续作推出时都会发生分裂。在围绕整个系列的讨论中，他写道，社群“每一代续作都会迅速壮大——然后分裂”。

• SyncError 认为，真正了解《Quake Champions》开发全过程的人可能寥寥无几。针对视频缩略图上的“到底发生了什么？”这一表述，他写道：“我真的觉得，我可能是唯一知道真相的人。”他补充说，Tim Willits 或许也知道，但“他现在已经不记得了”。

• 关于《Quake Champions》的开发过程，仍然有一些内容是 SyncError 不能讨论的。直播开始时，他表示自己的 NDA“永不过期”。他还解释称，违反合同义务可能带来诸如失去离职补偿金之类的后果。

• 《Retro Gamer》未来或许还会刊出更多有关《Quake Champions》设计理念的细节。SyncError 表示，自己最近接受了《Retro Gamer》的采访，内容涉及部分相同的设计理念。不过在直播当时，他还不知道这篇采访会刊登在哪一期。
