大航海时代ol的代理换了又换测了又测。

多希望能有个单机版的大航海时代ol啊

最近看到各种逆向REA的内容，掂量了下自己感觉没这个实力。

但是转念一下，我还原不了本体，但我做个MUD的文字版可以的吧？

于是我用以前玩台版的神圣导航软件的地图数据，加上扒下来的巴哈大航海ol数据库，然后尝试着用workbuddy+deepseekV4 做了一个网页版的大航海时代ol的文字单机版。

尽量还原了游戏里的大多数功能。

纯免费项目，后续也会持续更新。

目标嘛是尽量还原大部分游戏的单机玩法和体验。修改原版游戏里不人性化和纯消磨时间的部分

数据和公式尽量都用了原版游戏的内容。但问题很多,bug也很多。还有不少玩法不适合页游玩法的我要慢慢改。

现在只能说是个实验性技术验证品。

先放出来让大家帮我测试测试。看看还有哪些不到位的内容。我慢慢做慢慢改。实在不好玩大家当个BGM播放器听听音乐也是好的。

欢迎回帖批评或者加群批评。

已破解登录网关 9070 的帧格式、op 0x15/0x14/0x17 握手方式，以及服务器列表改写：把 4 个服务器的 IP 定长改成 192.168.001.7，0x22 版本服绝对不能改。

已破解游戏服握手：DH 1024 位（g=2，p 从真实服务器 529B 包里提取），密钥由 S 的 128 字节大端表示的前 8 字节取得，使用 Blowfish ECB，每 4 字节反转字节序，0x00 填充；在客户端内存里双向验证过（conn+0x44/0x84 及 key schedule 都对得上）。

已破解包结构：[2B 总长][0x63][段…]，段为 [2B 段长][2B cmd][2B seq][data]；客户端会把多条命令放在同一帧里，必须逐段拆，否则会误判、回错包，导致客户端黑屏。

流程层（登录 → 站进酒馆 → 对话）​

登录 → 版本校验 → 角色列表（7 角色 / 508B）→ 选服 → 进世界

0a05 世界数据 1760B → 0a02 场景 763B → 0e01 163B → AOI 0a29/0a2a/0a2b → 塞维尔冒险家公会 3D 场景完整渲染

这算是个技术验证。

服务端自主性（单机版的实际证明）​

完全不连台服：自己算 DH、自己加密、按请求签名查表回放，全在 9070 + 19060-63 本地

能改内容：retitle() 重算段长把会长改名成「單機版可行性驗證」、台词换成「這是本機單機版伺服器」——这证明客户端显示什么由我方服务端决定

二、离真单机版还差什么（按距离排序）

缺的东西        现状        补的难度

角色能不能走        0a0c 移动请求只收不回，0a1f 位置同步只收不回，角色实际不动        中：再抓一轮真实服务器的移动包与切场景包，一到两个命令族

世界是不是活的        场景是一次性快照，NPC、其他玩家都不会动        中偏大：要持续推 AOI 更新

面板数据        属性、技能、物品面板能打开（多处是客户端本地渲染），但数值全是包里的静态快照        小：只读够用；一旦要“写”（用道具、学技能、买卖）就得服务端状态机

商店、酒馆、任务、造船、投资        零覆盖，一个命令族都没抓        大：每类独立协议 + 业务逻辑

海上航行与战斗        零覆盖；航海图卡在「取得资料中」就是缺图数据包        很大

对话系统        死脚本，点一次从头讲、loop 重复最后一批        小：加个状态机就能变成“讲完给结束语”

账号与存档        全在内存查表，无账号库、无落盘        小到中：写个 sqlite 就完事

一句话结论：现在验证到的是「协议层完全可控 + 流程可任意伪造」，私服/单机在可行性和技术路线上已经没有悬念。但从“能进门”到“能生活”，差的不是距离，是工作量——缺的那层是「世界模拟」而不是「协议破解」：走路、AOI 刷新、商店、任务、战斗，每一项都要自己维护服务端状态并反推数据结构。按抓包回放的路子，能走到“静态世界 + 对话框”，再往前就必须转成“自己写游戏逻辑”，那是半个服务器重写的量级。

用人话就是能做，但是没有服务器端的数据全靠手搓可能是个天文数字的工作量。

我还是先修着网页版，然后看看以后能不能让Ai自己跑自己去拖服务器的数据吧，当然如果能走路捡到块装满服务器端的硬盘就更好了。
